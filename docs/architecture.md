# Архитектура AirGuard

## Назначение

AirGuard — утилита пассивного аудита защищённости беспроводных сетей Wi-Fi
для macOS. Она собирает открытую информацию о точках доступа вокруг,
оценивает уровень риска каждой сети и формирует отчёт с рекомендациями.
Инструмент не проводит атак (не подключается к сетям, не перехватывает
трафик, не подбирает пароли).

## Общая схема

```
┌──────────────────────────┐     JSON      ┌───────────────────────────┐
│  Swift-коллектор (.app)   │ ────────────► │     Python-ядро           │
│  CoreWLAN + CoreLocation  │               │                           │
│  пассивный скан эфира      │               │  collector → risk →       │
└──────────────────────────┘               │  scanner → report         │
                                             └──────────────┬────────────┘
                                                            │
                                          ┌─────────────────┴─────────────────┐
                                          ▼                                   ▼
                                   терминал (rich)                   HTML-отчёт (jinja2)
```

## Два уровня аудита

1. **Аудит эфира (основной).** Swift-коллектор через CoreWLAN получает
   список всех точек доступа в радиусе приёма: SSID, BSSID, шифрование,
   сигнал, канал, диапазон. Python-ядро оценивает риск каждой.

2. **Аудит своей сети (режим `--deep`).** Через nmap сканируется только
   та подсеть, к которой подключён компьютер, — ищутся устройства и их
   открытые порты. Сканирование чужих сетей не выполняется.

## Почему два языка

- **Swift + CoreWLAN** — единственный поддерживаемый Apple способ получить
  данные Wi-Fi на современных macOS (утилита `airport` удалена). Собран как
  `.app`-бандл, потому что macOS 26 отдаёт реальные SSID/BSSID только
  приложению, зарегистрированному как потребитель геолокации.
- **Python** — вся логика оценки, отчётов и CLI; быстрее разрабатывать и
  тестировать.

## Ограничение macOS 26 (Tahoe)

CoreWLAN скрывает SSID и BSSID у процесса без разрешения Location Services,
причём скрытый скан не возвращает ошибку — он отдаёт сети с пустыми
идентификаторами. Более того, проверяется не просто наличие разрешения, а
регистрация процесса как активного потребителя геолокации. Поэтому
коллектор перед сканированием запускает `CLLocationManager` и прокручивает
RunLoop до подтверждения (модуль `LocationGate`).

## Структура проекта

```
airguard/
├── src/
│   ├── collector/        Swift: сбор данных (CoreWLAN)
│   └── airguard/         Python: ядро (cli, collector, risk, scanner, report)
├── rules/                критерии оценки риска (YAML)
├── templates/            шаблон HTML-отчёта
├── tests/                модульные тесты логики оценки
├── docs/                 документация
├── examples/             примеры отчётов
├── install.sh            сборка Swift + установка зависимостей
└── pyproject.toml        метаданные пакета
```

## Правовые и этические аспекты

- Пассивный приём beacon-фреймов — это публично вещаемая информация,
  её сбор законен.
- Активные воздействия не выполняются.
- Режим `--deep` ограничен собственной подсетью.
- MAC-адреса точек маскируются в отчётах; данные не покидают компьютер.
